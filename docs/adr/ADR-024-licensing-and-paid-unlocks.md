# ADR-024: Licensing and paid cosmetic unlocks

Date: 2026-10-09. Status: licensing decided (below); paid unlocks are a draft for later decision. Nothing is implemented.

## Context

kolo is meant to stay open source. Besides the optional paid hosted server (ADR-017,
ADR-018, plan F7), the owner wants small one-time income without paywalling what a
shop needs to trade. The repository has no LICENSE file yet. ADR-018 and
`architecture.md` require that no online license check is needed to open a till.

Anyone can fork an open-source app and remove a check. The one-time payment is
therefore a convenience/support purchase of the official app, not DRM. The license
and a trademark policy protect the project, not code obfuscation.

## Licensing decision (2026-10-09)

- **Clients and shared packages** (`apps/desktop`, `apps/mobile`, `packages/*`):
  GPL-3.0-only (LICENSE files and package `license` fields added 2026-10-09; the server is
  marked `UNLICENSED`). The in-app terms state the GPL grant and that the names/logos are not licensed.
- **Server** (`apps/server`): closed source for now, to be opened later (licence then
  to be chosen; AGPL-3.0 is the natural fit, see below). It must move to a private
  repository, or the monorepo must stay private, before any public release.
- Running a closed server that uses GPL packages is allowed, because GPL duties start
  only on distribution. Distributing a closed *self-hosted* server image is
  distribution: it is only possible while hblabs owns all copyright in the GPL
  packages it includes. Outside contributions therefore need a CLA (or a licence
  exception) before they are accepted.
- **Trademark:** the "kolo" name, logo and "hblabs" credit are not licensed for forks.
  Forks must rename. Official builds are what customers pay for.
- The CLA must also keep hblabs able to publish to app stores (Apple's terms conflict
  with GPL for third-party contributions).
- Verify dependency compatibility (MIT/Apache-2.0/BSD are compatible with GPLv3).

### GPL vs AGPL

GPL obliges whoever *distributes* a modified binary to publish source. Desktop and
mobile apps are distributed, so GPL already covers them. AGPL adds the same duty for
modified software *offered over a network*. That matters only for the server: under
GPL, a competitor could modify `apps/server`, sell hosted sync and never publish their
changes; under AGPL they must. AGPL is the usual choice when hosted service is the
business model. Its costs: some companies refuse AGPL code, and Apple's App Store
terms conflict with (A)GPL for third-party contributions (hence the CLA/exception).

## Free forever

All operations (sales, stock, credit, returns, reports, staff), shop name/address/
phone/tax ID on receipts, paper width and printer setup, backups, export/restore,
peer pairing and exchange, both languages. The free/paid line is published in the
README as a promise and only moves toward free.

## One-time "kolo Pro" unlock (cosmetic)

Per shop, all its devices, valid for the current major version. Candidate price
5,000–10,000 XAF, payable by MTN MoMo / Orange Money.

- Remove "Generated by kolo · made by hblabs" from receipts
- Shop logo on receipts and in the app header
- Custom header/footer, thank-you and return-policy lines
- Receipt templates/styles and accent colour
- Later: branded PDF quotes, proformas and invoices

The default credit is free distribution; price the removal so most shops keep it.

## Proposed mechanism

- hblabs signs a token (Ed25519) containing workspace ID, unlocked features, major
  version and issue date. The public key is built into the apps.
- Entered as a QR code or short typed code; verified offline by a pure core function.
- Stored as an event so it reaches the shop's other devices through existing exchange.
- Missing or invalid token only restores the defaults (credit shown, no logo); it
  never blocks a trading operation.
- Start manual: payment over WhatsApp/MoMo, tokens issued with a small CLI. Automate
  through a payment provider (CinetPay, Notch Pay, Campay) only once demand is proven,
  reusing F7 webhook handling.
