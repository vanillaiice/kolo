# KOLO landing page

Static English/French website built with [Astro](https://astro.build) (static
output, no UI framework). Both language pages work without JavaScript. From the
repository root:

```sh
npm run dev:landing              # dev server at http://127.0.0.1:4173
npm run check:landing            # build, content/link/CSP checks and tests
npm run refresh:landing-releases # fetch GitHub releases into the saved snapshot
npm run build:landing            # offline build from the saved snapshot
```

Deploy `apps/landing/dist` to any static host. The public URL comes from
`content/site.json`; override it with `LANDING_SITE_URL`. For subpath previews,
set `LANDING_BASE_PATH` (for example `/kolo/`) at build time. Builds emit bilingual policy pages,
a blog with one RSS feed per language, social metadata, schema.org JSON-LD, a 404 page,
`sitemap.xml` and `robots.txt`.

## Deployment

The Kamal service uses Caddy behind kamal-proxy. Configure the server, SSH user
and domain in `config/deploy.yml`, point DNS at the server, and set the public URL.
Requires Kamal 2.12, compatible Ruby, Node.js, Docker/Buildx and SSH access.
Use `KAMAL_BIN` to override the `kamal` executable. From the repository root:

```sh
apps/landing/bin/deploy config
apps/landing/bin/deploy setup # first publication
apps/landing/bin/deploy       # updates
apps/landing/bin/deploy logs
apps/landing/bin/deploy rollback <version>
```

Setup and deployment rebuild and validate before publishing. Images use the
local `localhost:5555` registry forwarded over SSH. kamal-proxy handles HTTPS;
Caddy serves the site and `/up`. Verify both languages, policy pages, assets,
`/up`, missing-path 404s and other sites sharing the proxy after deployment.

## Editing

| Path | Purpose |
| --- | --- |
| `content/site.json` | Public URL, operator/contact details and hosting notices |
| `content/en.json`, `content/fr.json` | Visitor copy; keep keys and array lengths aligned |
| `content/releases.json` | Saved GitHub release snapshot; refresh after publishing |
| `src/pages` | Routes: language entry, `[lang]/` home, `[lang]/[policy]/`, `[lang]/blog/` (index, posts, RSS), sitemap and robots |
| `src/content/blog/{en,fr}` | Blog posts (MDX); see [Blog](#blog) |
| `src/content.config.ts`, `src/lib/blog.ts` | Post frontmatter schema; posts by language with their translations |
| `src/components`, `src/layouts/Base.astro` | Page sections, header/footer, `Video` and the document shell (metadata, alternates, feed link) |
| `src/lib/content.ts` | Loads copy, the selected release and settings; `href()` adds the base path |
| `src/lib/screenshots.ts` | Resizes `docs/screenshots/*.png` into AVIF/WebP `srcset` variants at build time |
| `src/lib/seo.ts` | JSON-LD: WebSite and SoftwareApplication (home), Blog, BlogPosting and breadcrumbs |
| `src/lib/releases.mjs`, `src/lib/platform.mjs` | Release selection and device suggestion, with their Node tests |
| `src/scripts/site.js` | Optional enhancements (language, device suggestion, lightbox, scroll reveal), bundled into one external module |
| `src/styles/global.css` | Tokens and all page styles; Inter comes from `@fontsource-variable/inter` |
| `astro.config.mjs` | Site/base URLs, CSP-safe build settings and the copy of repository files |
| `check.mjs` | Translation parity, links/anchors/media, no inline scripts or styles, sitemap, RSS, video host CSP |
| `public/media` | Optional local videos, posters and captions (`media/…` paths) |
| `public/guides` | Quick-start and slide PDFs; regenerate with `npm run export:landing` in `docs/guides/slides` |
| `public/assets/share.svg`, `share.png` | Social image; regenerate PNG after SVG edits |

The Caddy CSP allows only same-origin scripts and styles, so the build never inlines
them (`inlineStylesheets: 'never'`, `assetsInlineLimit: 0`) and `check.mjs` fails on
any inline `<script>`, `<style>`, `style=` or event-handler attribute.

Downloads use uploaded, nonempty assets from the newest shared `vX.Y.Z` release,
including prereleases. Missing assets link to GitHub Releases. Builds require no
GitHub access. At build start, `astro.config.mjs` copies the icon, logos, screenshots,
font licence and promoter descriptions from the repository into gitignored paths
under `public/` (`assets/kolo-icon.svg`, `assets/inter-LICENSE.txt`, `kit/`).

Screenshots come straight from `docs/screenshots`: the build makes AVIF and WebP
variants at several widths (desktop up to 2048 px, phone up to 480 px) with `sizes`
matched to each frame, and the lightbox opens the largest WebP. Replace a PNG there and
rebuild; nothing is regenerated by hand. Unreferenced originals are pruned from `dist`.

Motion is CSS plus a small observer in `site.js`: the hero moves in (transform only, so
the largest paint is not delayed), sections below the fold fade in as they scroll into
view, and cards lift on hover. Nothing is hidden without JavaScript, with
`prefers-reduced-motion: reduce`, or when printing.

Missing paths get `404.html` (bilingual, `noindex`) through Caddy's `handle_errors`,
with status 404 and the same security headers.

## Blog

Posts are MDX files in `src/content/blog/en/` and `src/content/blog/fr/`. The file
name is the URL (`/en/blog/<name>/`, lowercase words joined by hyphens); the same
name in both folders links a post to its translation, and a post may exist in one
language only. The other language's blog lists it under "Only in French/English".

```mdx
---
title: Selling on credit with KOLO
description: One or two sentences for the list, search results, social cards and RSS.
date: 2026-11-02
updated: 2026-11-05 # optional
draft: true         # optional; drafts appear only on the dev server
---

Body text. Headings start at `##`.
```

Code blocks are not syntax-highlighted: highlighters emit inline styles, which the
CSP blocks. Drafts in `welcome.mdx` show the format; delete them before the first post.

## Videos

`<Video>` works in pages and, without an import, in posts:

```mdx
<Video src="media/demo.mp4" poster="media/demo-poster.webp"
  captions={{ en: "media/demo-en.vtt", fr: "media/demo-fr.vtt" }} title="Optional heading" />
```

Paths starting with `media/` are served from `public/media`. Videos are not committed
there by default, so for larger files set `mediaBase` in `content/site.json` to the
external host (`"https://media.example.com/kolo/"`, HTTPS, ending in `/`) and use
absolute URLs under it. Setting it:

- adds a Videos section naming the host to both privacy policies;
- requires adding the host's origin to `media-src` and `img-src` in the `Caddyfile`
  CSP (posters and captions come from it too); `npm run check:landing` fails until you do,
  and fails on any video URL outside `mediaBase`.

Videos load nothing before play (`preload="none"`), but a poster from the external host
is fetched with the page. For the gallery demo video, set `video` in `content/media.json`
to `src`, `poster`, `captionsEn` and `captionsFr` paths or URLs.

## Privacy

Policy pages describe this website's local assets, language preference, server
logs and GitHub links. The script stores `kolo-landing-language` only after an
explicit language choice; the cookie page can remove it. To highlight the matching
download, it reads the browser's reported device type in the page only; nothing is
stored or sent. Visit statistics come from Umami, self-hosted by hblabs at
`stats.hblabs.xyz` (no cookies, nothing stored in the browser); the privacy policy
describes what it receives and the CSP allows only that origin. There are no
embedded third-party players or trackers; an external video host is named
automatically once `mediaBase` is set. Set log retention in both languages once confirmed from
the host. Update notices when hosting, cookies, forms, media or storage change.
